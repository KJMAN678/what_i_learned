# 週報を作る

`daily/` の日報をまとめて、`weekly/<月曜の日付>.md` を1つ作る。コミットと push はしない。

## 手順

1. 対象週を求める。`node scripts/week.ts $ARGUMENTS` を実行し、出力 `<monday> <sunday>` を得る。失敗したら、エラーメッセージをそのまま報告して終了する。
2. `weekly/<monday>.md` があれば、作らずに「既にあります。作り直すなら先にそのファイルを消してください」と報告して終了する。
3. `daily/<monday>.md` 〜 `daily/<sunday>.md` のうち存在するものをすべて読む。1つもなければ、作らずに「この週（<monday>〜<sunday>）の日報がありません」と報告して終了する。
4. `weekly/*.md` の frontmatter にある `tags` を集める。今回のタグは、同じ意味の既存タグがあればその表記を使い、なければ新しく付ける（1個以上）。
5. `weekly/<monday>.md` を次の形で書く。
6. `npm run check` を実行し、失敗したら直す。
7. 作ったファイルのパスと、付けたタグを報告する。

## 週報の形

```markdown
---
tags: [MCP, Docker]
summary: 一行のまとめ
---

## 今週学んだこと
- ...

## 気になった技術情報
- ...

## 来週やりたいこと
- ...
```

## 書き方のルール

- 日報に書かれていないことを足さない。推測や一般論で補わない。
- 日報の「〜〜」のような未記入の部分は、そのまま写さず、書かれていない項目として省く。
- `## 来週やりたいこと` は、日報に「やってみたい」「しようと思った」などの記述があるものだけを拾う。なければ `- （日報に記載なし）` と書く。
- `summary` は1行で、その週の主な学びを書く。
- 同じ項目が複数日にあるときは1つにまとめる。
- 日本語で書く。専門用語・固有名詞は日報の表記に合わせる。
