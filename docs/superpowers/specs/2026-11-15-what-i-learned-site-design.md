# 学んだことの記録サイト 設計（日報/週報版）

作成: 2026-11-15 / 改訂: 2026-11-16（日報は非公開、週報だけ公開に変更）
リポジトリ: `KJMAN678/what_i_learned`（現在は空）
公開先: `https://kjman678.github.io/what_i_learned/`

## 意図と背景

- **主目的:** 自分が後で見返して調べ直すための記録。
- **副目的:** 人に「自分はこんなことを学んでいる」と紹介する。
- 毎日の記録（日報）は自分だけが見る細かいメモにとどめる。人に見せるのは、日報を Claude Code にまとめさせた週報だけにする。
- 書く手間が少ないことと、後で探せることを最優先にする。

## ゴール

1. 日報を、`daily/YYYY-MM-DD.md` に自由な書式で書ける。サイトには出ない。
2. 週報を、Claude Code が日報から下書きし、ユーザーが壁打ちで直して公開できる。
3. 週報の一覧ページ（年度でグルーピング）で見渡せる。
4. 週報ごとに詳細ページがある（1週 = 1記事 = 1ページ）。
5. タグで絞り込める。全文検索で探せる。
6. 「この1ヶ月」ページで、直近4週の週報から何を学んだかを可視化する。
7. 週報の作成は2通りで行える。どちらも同じ `/weekly` スキルで動く。
   - 手元の Claude Code で `/weekly` を実行する。
   - GitHub の Actions 画面の [Run workflow] ボタンで実行する。結果は PR になる。

## 非ゴール

- 日報の公開、日報への書式チェック、日報へのタグ付けはしない。
- 週報の自動スケジュール実行（cron）はしない。実行は手動のみ。
- コメント、CMS、RSS、アクセス解析、多言語対応、下書き機能は作らない。
- 「この1ヶ月」ページに、タグの登場回数と週報を書いた週数以外の指標は載せない。

## アンチゴール

- 日報を書くのが面倒になること。日報には必須項目も書式もない。
- 未確認の週報が公開されること。公開の前に必ず、人が PR で確認する。
- 日報の中身がサイトに出てしまうこと。サイトの対象は `weekly/` だけ。

## 制約

- 公開サイトなので、週報はすべて公開される。
- リポジトリは公開（Public）。日報もリポジトリには入るので、GitHub 上では誰でも読める。Pages には出ない。ユーザーはこれを了承している。
- 年度は4月始まり。週の年度は、その週の月曜の日付で決める。
- 週は月曜〜日曜。タイムゾーンは Asia/Tokyo。
- 日報の書き方は、ユーザーの例に合わせた入れ子の箇条書き。「学習」「気になった技術情報」などの見出しの下に書く。

## 検討した方法

### サイトの作り方

| 案 | 内容 | 得意 | 苦手 |
|---|---|---|---|
| **A. Astro + Pagefind（採用）** | Markdown を Node で静的サイト化し、GitHub Actions で公開 | 年度別一覧、タグ、全文検索、集計を自由に作れる | Node と Actions の初期設定が要る |
| B. Jekyll | GitHub Pages 標準のビルド | 設定が最小 | 全文検索は別途 JS が必要。集計が書きづらい |
| C. MkDocs Material | 検索とタグが最初から付く | 検索とタグが最速 | 年度グルーピングと1ヶ月ページが型に合わない |

### 週報の作り方

| 案 | 内容 | 得意 | 苦手 |
|---|---|---|---|
| A. `CLAUDE.md` に手順を書くだけ | 頼むと動く | 追加ファイルなし | 出来上がりがぶれる |
| **B. 専用スキル `/weekly`（採用）** | 手順とひな形をスキルに固定する | 毎回同じ手順 | スキルのファイルが1つ増える |
| **C. GitHub Actions から実行（併用）** | 手動実行のボタンで、Actions 上で同じスキルを動かす | 手元の環境がなくても作れる。手順が1つで済む | 認証用の Secret の登録が要る。実行のたびに利用枠を使う |

ユーザーの選択: サイトは A、週報の作り方は B と C の併用。Actions の結果は **PR にする**（直接 `main` には入れない）。

## 設計（★はビルダーの判断）

### ファイルとフォルダ

```
daily/YYYY-MM-DD.md      日報。自由書式。Astro は読まない。
weekly/YYYY-MM-DD.md     週報。ファイル名は、その週の月曜の日付。
.claude/skills/weekly/SKILL.md   週報を作るスキル
.github/workflows/weekly.yml     手動実行で週報の PR を作る
.github/workflows/deploy.yml     main への push でサイトを公開する
```

### 週報ファイル

- frontmatter は `tags`（文字列配列、1個以上必須）と `summary`（任意）だけ。
- 書式違反はビルドを失敗させる。
  - `tags` がない、または空。
  - ファイル名が `YYYY-MM-DD.md` でない、実在しない日付、または月曜でない。
  - frontmatter が壊れている。
- push 前に気づけるよう、`npm run check` で同じチェックを手元で実行できるようにする。

```markdown
---
tags: [MCP, Docker, AWS, FBC]
summary: MCP本を読み始め、猫見守りの開発環境を整えた
---

## 今週学んだこと
- MCPサーバー開発大全: 〜〜が分かった
- 猫見守り: Docker sandboxes + SSH で開発できるようにした

## 気になった技術情報
- 〜〜の記事: 〜〜を試したい

## 来週やりたいこと
- 〜〜
```

### ページ

| URL | 内容 |
|---|---|
| `/` | 週報の一覧。年度ごとの見出しの下に、新しい週から順に「MM/DD〜MM/DD」・summary・タグを並べる。検索ボックスとタグ一覧を置く |
| `/weekly/YYYY-MM-DD/` | 詳細。「YYYY/MM/DD〜YYYY/MM/DD の週」を見出しに、タグ（タグページへのリンク）と本文を表示する ★ |
| `/tags/<tag>/` | そのタグが付いた週報の一覧（年度でグルーピング） ★ |
| `/recent/` | 直近4週の、タグ登場回数（多い順）と、週報を書いた週数（「N週 / 4週」） ★ |

### 検索とタグ

- 全文検索は Pagefind。ビルド後に索引を作り、一覧ページで使う。対象は週報の詳細ページだけ。
- `astro dev` では検索が動かない。確認は `build` + `preview` で行う。
- タグの絞り込みは、静的な `/tags/<tag>/` ページで行う。タグは大文字小文字を区別せず同じタグとして扱い、`C#` と `C++` と `C` が衝突しない URL にする。★

### 「この1ヶ月」

- 範囲は、今日（Asia/Tokyo）を含む週から数えて4週分（今週の月曜と、その3週前の月曜まで）。★
- 閲覧時の日付で集計するため、ビルド時に全週報の `{月曜の日付, タグ}` を JSON で埋め込み、ブラウザ側の JS で集計する。★ 理由: サイトは push したときしか再ビルドされないため。

### 週の計算

- `weekMonday(date)`: 日付から、その週の月曜の日付を返す。
- `fiscalYear(monday)`: 4月始まり。1〜3月は前年。
- 計算は純粋関数にまとめ、Node 標準のテストで検証する。★

### `/weekly` スキル

- 引数は任意の日付（`YYYY-MM-DD`）。その日を含む週を対象にする。省略した場合は、直前に終わった週（先週の月曜〜日曜）。
- 手順:
  1. 対象の週の月曜〜日曜の `daily/*.md` を読む。1つもなければ、週報を作らずその旨を報告して終わる。★
  2. `weekly/<月曜の日付>.md` がすでにあれば、上書きせずに報告して終わる。作り直したいときは、ユーザーがそのファイルを先に消してから実行する（この手順を `CLAUDE.md` に書く。サンプルの `weekly/2026-11-09.md` もこの方法で作り直す）。★
  3. 上のひな形で週報を作る。タグは、既存の週報（`weekly/*.md`）で使っている表記を優先して再利用する。★ `summary` は1行。
  4. コミットや push はしない。
- 週報が日報にない内容を書かない（日報にないことを推測で足さない）。★

### GitHub Actions: 週報の手動実行

- `weekly.yml` は `workflow_dispatch` で動く。入力は任意の日付 `week`（空なら直前に終わった週）。
- `anthropics/claude-code-action` で `/weekly <week>` を実行し、結果の `weekly/<月曜の日付>.md` だけを変更したブランチを作り、`main` への PR にする。
- 日報は、実行前にユーザーが push しておく。Actions はリポジトリ上の日報を読むため。
- 認証は Secret に登録する。名前は `CLAUDE_CODE_OAUTH_TOKEN` とする。★ action の入力名や PR の作り方は、ビルド時に公式ドキュメントで確認する。
- ユーザーの手作業が3つある。
  1. Secret の登録。
  2. リポジトリの Settings → Actions → General で「Allow GitHub Actions to create and approve pull requests」を有効にする。
  3. Settings → Pages で Source を「GitHub Actions」にする。
- ワークフローのファイルが `main` に入るまで、[Run workflow] ボタンは表示されない。

### 公開

- `deploy.yml` は、`main` への push でビルドして公開する。PR をマージすると公開される。
- `astro.config` の `site` は `https://kjman678.github.io`、`base` は `/what_i_learned`。

### 見た目

- フレームワークや UI ライブラリは使わず、素の CSS で作る。ライト/ダーク両対応。`lang="ja"`。凝らない。★

### 初期データ

- `daily/2026-11-15.md`: ユーザーの例。「〜〜」の部分は後で書き換える。★
- `weekly/2026-11-09.md`: 動作確認用のサンプル。例を元にした週報のひな形。後でユーザーが `/weekly 2026-11-09` で作り直す。★
- `CLAUDE.md`: 日報と週報の置き場所と書式、`/weekly` の使い方、`npm run check` を短く書く。★

## ビルダーに任せること

- Astro のバージョン、ディレクトリ構成、Content Collections の細かな書き方。
- CSS の細部、タグ一覧の見せ方、ファイルの分け方。
- テストランナーの選定（Node 標準で足りるなら追加しない）。
- `claude-code-action` の設定の細部。

## 検証の目安

- `build` が通り、`preview` で `/`、詳細、`/tags/...`、`/recent/` が開ける。
- 検索ボックスに週報内の語を入れるとヒットする。
- `daily/` の内容がサイトの出力（`dist/`）に含まれない。
- 週と年度のテスト（月曜の求め方、3月31日と4月1日、4週の境界）が通る。
- Actions: 公開用のワークフローが成功する。週報用のワークフローは、初回の手動実行で PR ができることを確認する（手元では検証できない）。
