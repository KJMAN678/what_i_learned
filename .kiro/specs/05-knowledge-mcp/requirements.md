# Requirements Document

## Project Description (Input)
### Problem
開発中に困ったとき、過去に同じような技術を学んだ・試したことがあっても思い出せず、ログを探しに行く手間もかかる。Claude Code での作業中に、自分の過去の知見を自然に呼び出したい。

### Current State
daily-log-page によりログ（`YYYY-MM-DD.md`、tags、本文）と共有パーサ `wil.records` がある。サイトには全文検索があるが、Claude からは使えない。

### Desired Outcome
- ローカルで動く MCP サーバーを Claude Code に登録すると、「今困っていること」（自然文やキーワード）を渡したときに、関連する過去ログの該当箇所を日付・tags・抜粋つきで返す
- 特定の日のログ、特定タグのログを取得できる
- サーバーはローカルのリポジトリ内ログを直接読み、外部サービスに送信しない

### Approach
MCP Python SDK（FastMCP）で stdio の MCP サーバーを `wil` パッケージ内のサブモジュールとして作る。ログの読み込みは `wil.records` を使う。関連度判定はまず標準ライブラリで足りる素朴な方法（キーワード・tags 一致、見出し単位の抜粋）から始め、埋め込み検索などは要求と設計で必要性を判断する。

### Constraints（brief より）
- ローカル専用。ネットワーク送信なし
- 依存は MCP SDK を基本とし、検索のための重い依存は必要性が示されるまで入れない
- タグ正規化・技術インデックスは tech-timeline が所有する

## Introduction
サイトのオーナーが Claude Code で開発作業をしているときに、自分が過去に書いた学習ログから、いま困っていることに関連する知見を Claude 経由で呼び出せるようにする。オーナーの手元で動くナレッジ MCP サーバーを Claude Code に登録しておくと、Claude は「困りごと」（自然文やキーワード）を渡して関連する過去ログの該当箇所を日付・tags・抜粋・公開ページの URL つきで受け取れる。あわせて、特定の日のログの取得と、特定タグのログの一覧ができる。サーバーはリポジトリ内のログを読むだけで、ログを外部に送信せず、自身では LLM を呼ばない（要約や解釈は呼び出し側の Claude が行う）。

## Boundary Context
- **In scope**:
  - Claude Code から呼び出せるローカルのナレッジ MCP サーバーと、その登録手順
  - 3 つの機能: 困りごとに関連する過去知見の検索、日付指定のログ取得、タグ指定のログ一覧
  - 結果の形式（日付、tags、summary、該当見出し、抜粋、公開ページの URL）
  - 検索・取得ロジックの自動テスト
- **Out of scope**:
  - 公開サイトへの組み込み（公開サイトは実行時サーバーを持たない）
  - タグの正規化・別名の統合・技術インデックス（tech-timeline が所有）。本機能はタグを書かれたとおりに扱い、比較時に大文字小文字の違いだけを同一視する
  - 学習のおすすめ（learning-recommendation）、ログの作成・編集（log-writing-skill）
  - 埋め込みベクトル等による意味検索（語句の一致で不足することが示されるまで扱わない）
- **Adjacent expectations**:
  - ログの形式・読み取り・検証規則・公開ページの場所は daily-log-page の共有読み取り機能に従い、本機能で独自に解釈しない
  - 公開ページの URL は daily-log-page が定めるサイトのベース URL とログのページ位置から得る

## Requirements

### Requirement 1: 困りごとに関連する過去知見の検索
**Objective:** サイトのオーナーとして、Claude Code での作業中に困りごとを伝えるだけで関連する過去ログの該当箇所を受け取りたい。ログを探しに行く手間をなくし、過去の知見を作業に活かすため。

#### Acceptance Criteria
1. When 呼び出し元が困りごと（自然文またはキーワード）を渡して検索する, the ナレッジ MCP サーバー shall 全ログの見出し単位の区間を対象に、困りごとに含まれる語句と一致する区間を関連度の高い順に返す
2. The ナレッジ MCP サーバー shall 語句がログの tags と一致する区間を、本文のみに一致する区間より高い関連度として扱う
3. The ナレッジ MCP サーバー shall 語句の一致判定で英字の大文字・小文字を区別しない
4. When 困りごとが空白で区切られていない日本語の文である, the ナレッジ MCP サーバー shall 文中に含まれる語句と一致する区間を見つけて返す
5. When 関連度が同じ区間が複数ある, the ナレッジ MCP サーバー shall 日付の新しいログの区間を先に返す
6. When 呼び出し元が返す件数の上限を指定する, the ナレッジ MCP サーバー shall 指定件数以下の結果を返す
7. If 件数の上限が指定されない, the ナレッジ MCP サーバー shall 最大 10 件の結果を返す
8. If 指定された件数の上限が 1 未満または 50 を超える, the ナレッジ MCP サーバー shall 検索を行わず、指定できる範囲（1〜50）を示すエラーを返す
9. If 一致する区間が 1 つもない, the ナレッジ MCP サーバー shall エラーではなく、結果が 0 件であることが分かる応答を返す
10. If 困りごとが空または空白のみである, the ナレッジ MCP サーバー shall 検索を行わず、困りごとの入力が必要であることを示すエラーを返す

### Requirement 2: 検索結果の形式
**Objective:** 呼び出し側の Claude として、各結果の出典と該当箇所を項目ごとに受け取りたい。オーナーに根拠を示し、必要なら元ページへ案内するため。

#### Acceptance Criteria
1. The ナレッジ MCP サーバー shall 各検索結果に、ログの日付（`YYYY-MM-DD`）、tags（書かれたとおりの文字列と順序）、summary（無い場合は無いと分かる値）、該当区間の見出し、抜粋、公開ページの URL を含める
2. The ナレッジ MCP サーバー shall 公開ページの URL を、サイトのベース URL（`https://kjman678.github.io/what_i_learned/`）にログのページ位置（`logs/YYYY-MM-DD/`）を連結した完全な URL として返す
3. If 一致した区間がログの最初の見出しより前の本文である, the ナレッジ MCP サーバー shall 見出しが無いと分かる値を返す
4. The ナレッジ MCP サーバー shall 抜粋を該当区間の本文から作り、300 文字を超える場合は 300 文字以内に切り詰め、切り詰めたことが分かる印を付ける
5. The ナレッジ MCP サーバー shall 検索結果を、呼び出し元が項目ごとに取り出せる構造化した形式で返す

### Requirement 3: 日付指定のログ取得
**Objective:** サイトのオーナーとして、「あの日に何を学んだか」を Claude から直接読みたい。検索結果で見つけたログの全体を確認するため。

#### Acceptance Criteria
1. When 呼び出し元が日付（`YYYY-MM-DD`）を指定してログを取得する, the ナレッジ MCP サーバー shall その日のログの日付、tags、summary、公開ページの URL、本文全体、見出しの一覧を返す
2. If 指定された日付のログが存在しない, the ナレッジ MCP サーバー shall その日付のログが無いことを示すエラーを返す
3. If 指定された日付が `YYYY-MM-DD` 形式でない、または暦上存在しない日付である, the ナレッジ MCP サーバー shall 期待する形式を示すエラーを返す

### Requirement 4: タグ指定のログ一覧
**Objective:** サイトのオーナーとして、特定の技術タグを付けたログを一覧したい。ある技術について過去に何度・いつ学んだかを把握するため。

#### Acceptance Criteria
1. When 呼び出し元がタグを指定して一覧を求める, the ナレッジ MCP サーバー shall そのタグを持つすべてのログについて、日付、tags、summary、公開ページの URL を、日付の新しい順に返す
2. The ナレッジ MCP サーバー shall タグの比較で英字の大文字・小文字の違いだけを同一視し、それ以外の表記揺れ（別名、記号、空白の違い）を同一視しない
3. The ナレッジ MCP サーバー shall 結果のタグを、正規化せずログに書かれたとおりの文字列で返す
4. If 指定されたタグを持つログが無い, the ナレッジ MCP サーバー shall エラーではなく、結果が 0 件であることが分かる応答を返す
5. If 指定されたタグが空または空白のみである, the ナレッジ MCP サーバー shall タグの入力が必要であることを示すエラーを返す

### Requirement 5: ログの読み込みと最新性
**Objective:** サイトのオーナーとして、公開サイトと同じ解釈で最新のログが参照されてほしい。書いたばかりのログもすぐ呼び出せ、壊れたログに気づけるようにするため。

#### Acceptance Criteria
1. The ナレッジ MCP サーバー shall ログを daily-log-page の共有読み取り機能を通じて読み、公開サイトと同じ規則で解釈する
2. When ログが追加・変更・削除された後に要求を受ける, the ナレッジ MCP サーバー shall 再起動なしでその変更を反映した結果を返す
3. If 読み取り対象に不正なログが含まれる, the ナレッジ MCP サーバー shall 不正なログを黙って除外せず、該当するすべてのファイルパスと理由を含むエラーを返す
4. If リポジトリのログの置き場所が見つからない, the ナレッジ MCP サーバー shall ログの置き場所が見つからないことと、確認すべき起動時の設定を示すエラーを返す
5. While ログが 1 件も無い, the ナレッジ MCP サーバー shall 検索・タグ一覧に結果が 0 件であることが分かる応答を返す
6. While ログが 1,000 件以下である, the ナレッジ MCP サーバー shall 各要求に 2 秒以内に応答する

### Requirement 6: ローカル完結と安全性
**Objective:** サイトのオーナーとして、ログの内容が手元から外に出ないことを保証したい。公開前の下書きや作業中の情報を外部に送らないため。

#### Acceptance Criteria
1. The ナレッジ MCP サーバー shall ネットワークへの送信を行わず、手元のプロセスとして呼び出し元とだけやり取りする
2. The ナレッジ MCP サーバー shall 外部 API や LLM を呼び出さない
3. The ナレッジ MCP サーバー shall ログを読み取るだけで、ファイルを作成・変更・削除しない
4. The ナレッジ MCP サーバー shall 呼び出し元の入力にかかわらず、リポジトリのログの置き場所以外のファイルを読み取らない（サイトのベース URL を得るための設定ファイルを除く）

### Requirement 7: Claude Code への登録と使い方
**Objective:** サイトのオーナーとして、一度登録すればどのプロジェクトで作業していても過去知見を呼び出せるようにしたい。困ったときに準備なしで使えるようにするため。

#### Acceptance Criteria
1. The ナレッジ MCP サーバー shall Claude Code に登録して、このリポジトリ以外のプロジェクトでの作業中にも利用できる手順を手順書に持つ
2. The 手順書 shall 登録コマンドの例で、オーナー個人の環境に固有の絶対パスではなく、置き換えるべき箇所が分かるプレースホルダを使う
3. The ナレッジ MCP サーバー shall 各機能に、呼び出し側の Claude が使い分けられる目的・入力・出力の説明を付け、検索機能の説明では困りごとから主要な語句を渡すとよいことを示す
4. When Claude Code が登録されたナレッジ MCP サーバーを起動する, the ナレッジ MCP サーバー shall 3 つの機能（検索、日付指定取得、タグ指定一覧）を呼び出し元に提示する

### Requirement 8: 自動テスト
**Objective:** サイトのオーナーとして、検索や取得の振る舞いが変更で壊れていないことを確認したい。安心して改良を重ねるため。

#### Acceptance Criteria
1. The ナレッジ MCP サーバー shall Requirement 1・2 の検索の振る舞い（関連度の順序、tags 一致の優先、大文字小文字、日本語の文、同点時の日付順、件数上限、0 件、抜粋の切り詰め、URL）を確認する自動テストを持つ
2. The ナレッジ MCP サーバー shall Requirement 3・4・5 の取得・一覧・エラーの振る舞いを確認する自動テストを持つ
3. The ナレッジ MCP サーバー shall 自動テストを、ネットワークにも実際の Claude Code にも依存せず、一時的なテスト用ログで実行できるようにする
