# Implementation Plan

> 前提: daily-log-page の実装（共有ログモジュール、プロジェクト定義、サイト設定ファイル、README、テスト基盤）が完了していること。本計画はそれらを変更せず、依存の追加と README への節の追記だけを行う。

- [ ] 1. 基盤: MCP SDK の導入と前提の確認
- [ ] 1.1 公式 MCP Python SDK（2.x 系）を依存に加え、使う API が import できることを確かめる
  - 上流の共有ログモジュールが import でき、ログ一覧の読み込み・ログ置き場所の定数が設計どおりであることを確認する（違えば着手せず設計の再確認に戻る）
  - プロジェクトの直接依存に MCP SDK を 2.3 以上 3 未満の範囲で追加し、ロックファイルを更新する（extra は付けない）
  - サーバー生成クラス、ツール用エラー、インプロセス用クライアントの import 経路を確認し、設計・research と違えば research.md の未確認事項を更新する
  - `uv run --directory <パス>` が作業ディレクトリを移すことを確認する（移さない場合は登録手順の代替を 4.2 で使う）
  - 完了状態: `uv sync --frozen` が成功し、`uv run python -c "from mcp.server import MCPServer; from mcp.server.mcpserver.exceptions import ToolError; from wil.records import load_records, Record, Section, RecordsInvalid, CONTENT_DIR, LOGS_SUBDIR"` が成功し、`CONTENT_DIR` が作業ディレクトリ基準の相対パス `content` であることを確認でき、既存テストがすべて通る
  - _Requirements: 5.1_

- [ ] 2. 検索・取得ロジック（MCP に依存しない純ロジック）
- [ ] 2.1 語句抽出と結果の共通部品を作る
  - 困りごとの文を正規化（全角半角の統一、大文字小文字の同一視）し、英数字の語、カタカナの連続、漢字の連続（3 文字以上は 2 文字ずつの組も追加）を重複なく取り出し、ひらがな・記号を捨てる。何も取れないときは入力全体を 1 語にする
  - 公開ページの完全な URL（サイトのベース URL + ログのページ位置）、300 文字を超える本文を切り詰めて省略記号を付ける抜粋、利用者向けの日本語エラー、結果の型（検索結果、ログ概要、タグ一覧結果、ログ詳細、見出し）を用意する
  - 一時ディレクトリにログを書き、共有ログモジュールで読み込む小さなテスト補助を検索ロジックのテストファイル内に用意する（共通 fixture ファイルは作らず、各テストファイルが自前の補助を持つ）
  - 完了状態: 「Lambda のコールドスタートが遅い」から `lambda`・`コールドスタート`・`遅` が取れてひらがなを含まないこと、漢字 2-gram、全角・大文字の正規化、ひらがなのみの入力、URL の形、301 文字で 300 文字 + 省略記号になることを確かめる単体テストが通る
  - _Requirements: 1.3, 1.4, 2.2, 2.4, 8.1, 8.3_

- [ ] 2.2 困りごと検索を実装する
  - 全ログの見出し単位の区間を対象に、tags に一致した語句の数、区間の見出しと本文に含まれる語句の種類数、日付の新しさ、区間の出現順の順で並べる
  - tags だけが一致し本文に語句が無いログは、本文が空でない最初の区間を 1 件だけ候補にする
  - 件数上限（既定 10、1〜50 の外はエラー）、空の困りごとのエラー、一致なし・ログ 0 件での空の結果を扱う
  - 各結果に日付、書かれたとおりの tags、summary（無ければ無し）、見出し（最初の見出しより前なら無し）、抜粋、URL を入れる
  - 完了状態: tags 一致の優先、本文一致数による順位、同点時の新しい日付優先、tags のみ一致時の 1 件、上限の既定・指定・範囲外、空入力、0 件、各項目の値を確かめる単体テストが通る
  - _Requirements: 1.1, 1.2, 1.5, 1.6, 1.7, 1.8, 1.9, 1.10, 2.1, 2.3, 5.5, 8.1, 8.3_

- [ ] 2.3 日付指定の取得とタグ指定の一覧を実装する
  - 日付は `YYYY-MM-DD` 形式かつ暦上存在する日付のみ受け付け、読み込んだログの中から照合する（ファイルパスを組み立てない）。該当なしはその旨のエラー。本文全体と見出し一覧（最初の見出しより前の区間を除く）を返す
  - タグは前後空白を除き、大文字小文字だけを同一視した完全一致で照合し、日付の新しい順に概要を返す。返すタグは書かれたとおり。空のタグはエラー、該当なしは空の結果
  - 完了状態: 正常取得、存在しない日付、`2026-02-30`・`20261123`・`2026/11/23` のエラー、`AWS` で `aws` が一致し `aws-lambda` は一致しないこと、新しい順、書かれたとおりのタグ、0 件、空タグのエラーを確かめる単体テストが通る
  - _Requirements: 3.1, 3.2, 3.3, 4.1, 4.2, 4.3, 4.4, 4.5, 6.4, 8.2, 8.3_

- [ ] 3. MCP サーバー
- [ ] 3.1 呼び出しごとのログ読み込みとエラー変換を作る
  - サイト設定ファイルからベース URL を読み、無ければ利用者向けエラーにする
  - ログ置き場所が作業ディレクトリに無い場合は、置き場所・現在の作業ディレクトリ・登録コマンドの `--directory` の確認を促すエラーにする
  - 共有ログモジュールで毎回ログを読み込み（キャッシュしない）、不正ログはすべてのファイルパスと理由を列挙したツールエラーに、利用者向けエラーはそのメッセージのままツールエラーに変換する
  - 標準出力に書かず、ファイルを書き込まない
  - 完了状態: サーバーの結合テストファイル（3.3 と同じファイル）に置いた、一時ディレクトリを作業ディレクトリにしたテストで、正常時にログ一覧とベース URL が得られ、置き場所なし・設定なし・不正ログでそれぞれ期待するメッセージのツールエラーになる
  - _Requirements: 2.2, 5.1, 5.2, 5.3, 5.4, 6.3, 6.4_

- [ ] 3.2 3 つのツールを登録し、stdio で起動できるようにする
  - 困りごと検索（困りごと、件数上限 既定 10）、日付指定取得（日付）、タグ指定一覧（タグ）を、設計の名前・引数・戻り値の型で登録する。各ツールは 3.1 の読み込みを経て 2 章のロジックを呼ぶ
  - 各ツールと引数に、呼び出し側の Claude が使い分けられる日本語の説明を付け、検索の説明には主要な語句を渡すとよいこと・言い換えは拾えないことを書く。サーバーに用途の短い説明を付ける
  - モジュールとして実行すると既定の stdio で起動する入口を用意する
  - 完了状態: リポジトリルートで `uv run python -m wil.knowledge_mcp < /dev/null` がトレースバックなしで終了し、標準出力が空である（プロトコル以外を書かない）。ロジックとサーバーのモジュールに `print` が無い
  - _Requirements: 1.6, 1.7, 1.8, 2.5, 3.1, 4.1, 6.1, 7.3, 7.4_

- [ ] 3.3 サーバーをインプロセスで呼ぶ結合テストを書く
  - 一時ディレクトリにログとサイト設定ファイルを置いて作業ディレクトリにし、インプロセスのクライアントでサーバーを呼ぶ（テスト補助はこのテストファイル内に持つ）
  - ツール一覧が 3 つで説明を持つこと、検索の構造化結果の形、ログ追加後の再呼び出しで新しいログが現れること、不正ログ・置き場所なし・サイト設定なし・空の困りごと（利用者向けエラー）でエラー応答になり本文に理由が含まれること、ネットワーク接続を禁止しても 3 ツールが成功することを確かめる
  - ロジックとサーバーのモジュールが HTTP クライアントや LLM の SDK を import していないことを確かめる
  - サーバーをモジュールとして標準入力を閉じた状態で起動し、正常終了して標準出力が空であることを回帰テストとして残す
  - 完了状態: `uv run pytest` で結合テストがすべて通る
  - _Requirements: 2.5, 5.2, 5.3, 5.4, 6.1, 6.2, 7.4, 8.2, 8.3_
