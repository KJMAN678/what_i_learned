# Implementation Plan

> 前提: daily-log-page と log-index の全タスクが実装済みであること（`wil.records`、`wil.generated`、`wil.log_index`、`scripts/generate.sh`、`scripts/build.sh` の生成段、`.gitignore` と `ALLOWED_PATTERNS` の生成区域設定、`content/index.md`、`README.md`、pytest 設定が存在し、`./scripts/build.sh` と `uv run pytest` が成功する状態）。この spec はそれらを作らない。

- [ ] 1. 基盤: 表記ゆれの吸収と別名の対応表
- [ ] 1.1 照合キー、技術の識別子、別名の対応表とその検査を、テストを先に書いて実装する
  - 着手前に上記の前提が揃い、`./scripts/build.sh` と `uv run pytest` が成功することを確認する
  - 照合キーは log-writing-skill の比較キーと同一規則（NFKC → casefold → 空白と `- _ . ・` を除去）とし、結果が空なら前後の空白を除いた元の文字列にする
  - 別名の対応表は（表記, 表示名）の組の列としてモジュール内に置き、照合キーで照合して技術の識別子を返す。表を省略した呼び出しは呼び出し時点のモジュールの表を使う
  - 同じ表記の異なる表示名への対応、照合キーが同じで文字列が異なる表示名、別名の連鎖をすべて集めて 1 つの誤りとして送出し、自分自身への対応は許す
  - 完了状態: 生成器のテストで、`MCP`/`mcp`、`Next.js`/`nextjs`、全角/半角、`AWS Lambda`/`aws-lambda` の同一視、`C`/`C++` の区別、`-` のような空になる表記、別名経由の同一視（全角の別名を含む）、3 種の矛盾の検出と問題文への表記の記載、自己対応の許容がすべて成功し、モジュールは `wil.records` と `wil.generated` 以外の `wil.*` を読み込まない
  - _Requirements: 1.1, 1.2, 1.3, 1.7, 1.8, 8.2, 9.1_

- [ ] 1.2 技術別ページの場所の規則を、テストを先に書いて実装する
  - 技術の識別子から区域相対のページの場所を作る（`[a-z0-9]` はそのまま、それ以外の文字は `-16進コードポイント-` に置換、結果が `index` なら `index-`）
  - 完了状態: 場所のテストで、`aws` → `aws`、`c++` → `c-2b--2b-`、日本語の識別子、`index` → `index-` が期待どおりになり、識別子が異なる複数の入力（記号・日本語・`index` を含む）で場所が重ならず、いずれも一覧ページと同じ URL にならないことが成功する
  - _Requirements: 2.6, 5.8, 9.3_

- [ ] 2. コア: 技術インデックス
- [ ] 2.1 学習日の抜粋を選ぶ規則を、テストを先に書いて実装する
  - 照合語（表示名と全表記）を NFKC + casefold で部分一致させ、見出しまたは本文が一致する最初の区間を選ぶ
  - その区間の本文のうちコードフェンス外で最初の空でない行、無ければ区間の見出し、一致区間が無ければ summary、それも無ければ本文のフェンス外・見出し行以外の最初の空でない行、何も無ければ空
  - 120 文字を超える場合は先頭 120 文字に「…」を付ける
  - 完了状態: 抜粋のテストで、大文字小文字・全角を無視した区間一致、フェンス内の行の除外、本文が空の区間での見出しの採用、summary への後退、本文冒頭への後退（見出し行を除く）、空の抜粋、121 文字の入力での省略がすべて成功する
  - _Requirements: 2.4, 3.1, 3.2, 3.3, 3.4, 3.5, 9.2_

- [ ] 2.2 技術インデックスの型と構築関数を、テストを先に書いて実装する
  - 設計の公開契約どおりの不変な学習日・技術の型（初回日・最終日・回数を含む）と、ログ列から技術インデックスを作る純関数を作る。構築の最初に別名の対応表を検査する
  - 1 ログ内で同じ技術を表す複数の表記は 1 件の学習日にまとめ、書かれた表記を順に残す。学習日は日付の古い順
  - 表示名は別名の表示名を優先し、無ければ最多のログで使われた表記（同数は文字列の昇順）。別表記は表示名以外の表記を昇順で保持する
  - 各技術に 1.2 の規則によるページの場所を持たせる。技術の並びは表示名の大文字小文字を無視した昇順
  - 完了状態: インデックスのテストで、技術の集合が tags と一致すること、学習日の並び、同一ログ内の重複の除去と書かれた表記、初回日・最終日・回数、表示名の決定（別名優先・最多・同数）、別表記の並び、各技術のページの場所が 1.2 の規則どおりであること、入力順に依存しない同一結果、ファイルを書かないこと、矛盾した別名の対応表を渡すと構築が別名の誤りを送出することがすべて成功する
  - _Requirements: 1.4, 1.5, 1.7, 2.1, 2.2, 2.3, 2.4, 2.5, 2.6, 2.7, 8.1, 8.3, 8.4, 9.2_

- [ ] 3. 技術ページの描画と生成器
- [ ] 3.1 技術一覧と技術別タイムラインの Markdown 描画を、テストを先に書いて実装する
  - 表示名・別表記・抜粋のエスケープは log-index の共有生成ヘルパーが提供するエスケープ関数（`wil.generated.escape_inline`）を使い、独自のエスケープ関数は置かない。log-index と同じ入出力例で描画結果をテストする
  - 一覧: 見出し「技術一覧」、総数の文（0 件では技術がまだ無い文）、技術ごとに技術別ページへのソース相対リンク・回数・初回日・最終日の 1 行
  - 技術別: 見出しを表示名、一覧へのリンク、初回日・最終日・回数、別表記（ある場合のみ）、古い順の学習日の行（ログへのソース相対リンクと、ある場合のみ抜粋）
  - 全ページの集合（一覧 + 各技術別）を返す描画関数を作る
  - 完了状態: 描画のテストで、一覧の見出し・総数・名前順・リンク先・回数と日付・0 件の文、技術別の見出し・一覧へのリンク・集計・別表記の有無・ログへのリンク・抜粋なし行の形、記号や HTML を含む表示名と抜粋のエスケープ、ページ集合のキー（0 件では一覧のみ）、同じ入力での同一出力がすべて成功する
  - _Requirements: 4.1, 4.2, 4.3, 4.4, 4.5, 4.6, 5.1, 5.2, 5.3, 5.4, 5.5, 5.6, 5.7, 6.3, 7.3, 9.3_

- [ ] 3.2 生成器をコマンドとして実行できるようにする
  - 入口では最初に別名の対応表を検査し、矛盾があれば問題を標準エラーに出して 1 を返し何も書かない。問題がなければ描画関数を共有生成ヘルパーに渡す
  - 完了状態: リポジトリルートで生成器を実行すると終了コード 0 で `content/generated/tech-timeline.md` と実際のサンプルログの技術別ページができる。テストで、矛盾した対応表に差し替えた入口が 1 を返し、標準エラーに問題が出て、生成区域に何も書かれないことが成功する。一時ディレクトリに不正なログを置いて入口（共有生成ヘルパー経由）を実行すると 1 を返し、そのパスと理由が標準エラーに出て何も書かれないことが成功する
  - _Requirements: 1.7, 2.8, 7.5_

- [ ] 4. 統合: 生成手順とサイトへの組み込み
- [ ] 4.1 生成手順に技術ページの生成器を登録する
  - 生成スクリプトの一覧生成器の行の下に 1 行だけ追加し、区域の削除と他の行は変えない
  - 完了状態: 生成スクリプトを実行すると一覧ページと技術ページが両方生成される。ログから tag を一時的に消して再実行すると、その技術のページが消える。一時的に不正なログを置くと非ゼロで終わりパスと理由が表示される。確認後に元に戻し、生成スクリプトが再び成功し `git status` に生成物と残骸が出ない
  - _Requirements: 2.8, 7.1, 7.2, 7.4, 7.5_

- [ ] 4.2 トップページの導線と手順書を追記する
  - トップページの末尾に技術一覧へのソース相対リンクの 1 行を追加し、既存の文は変えない
  - 手順書に「技術タイムラインと別名の対応表」の節を追加する（自動生成であること、自動で吸収される表記ゆれ、別名の追加方法、矛盾時はビルドが失敗すること、ログの書き換えは不要なこと、技術名は一覧から探すのが確実で組み込み検索は英数字のみ期待できること）
  - サイト設定に明示のナビが既にある場合は、その末尾に区分名「技術一覧」で一覧ページへの 1 項目だけを追加し、他の項目と順序は変えない（無い場合はナビを作らず、site-design が載せる）。技術別ページは載せない
  - 生成器の登録（4.1）の後に行う。先に追記すると生成前の厳格ビルドでリンク切れとして失敗するため（ナビの項目も、生成器が無いと無効なリンクになるため同様）
  - 完了状態: トップページの差分が追加 1 行のみで、サイト設定の差分はナビへの追加 1 項目のみ（ナビが無い場合は差分なし）で、生成物を消した状態から実行したビルド手順が追記したリンクを含めて成功する。手順書の新しい節に上記の内容が載っている
  - _Requirements: 1.6, 6.1, 6.2, 6.4, 6.5_

  - 完了状態: `site/generated/tech-timeline/index.html` と各技術別ページの `index.html` が存在し、厳格モードのビルドが成功する（一覧 → 技術別 → ログ、技術別 → 一覧のリンクが有効）。ナビゲーションに「技術一覧」があり、技術別ページがナビゲーションに並ばず、トップページのリンクが一覧を開く。ログ詳細ページとログ一覧ページの URL が変わっていない
  - 完了状態: 手元プレビューの組み込み検索で、英数字の技術の表示名と別表記を入力すると技術別ページが結果に出る。出ない場合は作業を止め、設計に戻す
