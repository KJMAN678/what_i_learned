# Implementation Plan

> 前提: daily-log-page と log-index の全タスクが実装済みであること（`zensical.toml`、`wil.records` とその許可リスト、`scripts/build.sh` と生成段、`content/index.md` と末尾の一覧リンク行、`README.md`、`pyproject.toml` の pytest 設定が存在し、`./scripts/build.sh` と `uv run pytest` が成功する状態）。この spec はそれらを作らない。tech-timeline の実装は前提にしない（あれば確認対象に含める）。

- [ ] 1. 基盤: 見た目の定義ファイルとテーマ設定
- [ ] 1.1 見た目の定義ファイルを公開許可リストで許可し、置き場所を作る
  - 着手前に上記の前提が揃い、ビルドスクリプトとテスト一式が成功することを確認する
  - 共有ログ読み取り機能の公開許可リストに、見た目の定義ファイル 1 つだけを許すパターンを 1 要素追加する（他の規則は変えない）
  - 公開コンテンツディレクトリの所定の場所に、目的を書いたコメントだけの見た目の定義ファイルを置く
  - 完了状態: 定義ファイルを置いた状態でログ検証コマンドが成功し、同じ場所に別名の CSS ファイルを一時的に置くと検証が失敗してそのパスが報告される。確認後に一時ファイルを削除し、既存のテスト一式が成功する
  - 見た目の定義ファイルはここでは空の置き場所だけを作り、規則は 3.x で書く
  - _Boundary: PublishAllowlist, ExtraStylesheet_
  - _Requirements: 8.5_

- [ ] 1.2 テーマ設定に配色 2 種・書体・ナビ補助・見た目の定義の登録を追加する
  - サイト設定に、端末設定に従うライト/ダークの 2 配色（日本語の切り替え名つき）、外部書体の読み込み停止、上部へ戻る操作と前後ページのリンクの機能、見た目の定義ファイルの登録を追加する。上流のキー（言語、タグ、公開ディレクトリ、URL）は変えない。ナビは 1.3 で扱う
  - 切り替えアイコンでビルドが失敗した場合は、設計に記載した代替アイコンに替える
  - 完了状態: ビルドスクリプトが成功し、生成 HTML に外部書体サービスへの参照が無く、切り替えボタンのツールチップと読み上げ名が日本語で、全ページが見た目の定義ファイルを相対パスで読み込む
  - 完了状態: 端末設定をダークにすると初回表示がダークになり、手動で切り替えた配色が別ページへの移動と再読み込みの後も保たれる。保たれない場合は独自の処理で補わず、要件の見直しが必要である旨を報告する
  - _Boundary: ThemeConfig_
  - _Requirements: 1.7, 4.1, 4.2, 4.3, 4.4, 5.3, 6.1, 6.2, 8.4_

- [ ] 1.3 ナビゲーションをトップと一覧ページだけの日本語の並びにする
  - サイト設定に明示のナビを追加し、ホーム（トップページ）→ 学習ログ一覧 → 技術一覧の順に、各一覧ページの H1 と同じ日本語の区分名で並べる。技術一覧は tech-timeline が実装済みの場合だけ載せる（生成器の無いページは載せない）。ログページと技術別ページは載せない
  - 完了状態: ビルドスクリプトが `--strict` 込みで成功し、ナビの各項目に対応する HTML（トップは `site/index.html`、一覧は `site/generated/<名前>/index.html`）が存在する。ナビには日本語の区分名だけが決まった順で出て、ログの日付は並ばない。ログページは一覧ページのリンクから開ける
  - 完了状態: ナビに載らないページについての警告でビルドが失敗した場合は、`not_in_nav` でログと技術別ページを外して成功させる
  - _Depends: 1.2_
  - _Boundary: SiteNav_
  - _Requirements: 6.2, 10.1, 10.2_

- [ ] 2. 設定の回帰テスト
  - サイト設定を読み、見た目の定義の登録がちょうど 1 件でその参照先が存在すること、言語が日本語でタグ機能が有効なこと、外部書体の停止、2 配色と日本語の切り替え名、独自スクリプトとテンプレート上書きが無いことを検査するテストを書く
  - 公開許可リストが見た目の定義ファイル 1 つだけを許し、別名の CSS やディレクトリ外の CSS を許さないことを検査する
  - ナビが、ホームを先頭に、日本語の区分名とパスの平らな組だけで、パスがトップか生成区域直下の一覧ページだけを指すことを検査する（生成ページの存在は検査しない）
  - 完了状態: テスト一式が成功し、設定の見た目の定義の参照を一時的に存在しない名前に変えるとこのテストが失敗する（確認後に戻す）
  - 完了状態: ナビにログページのパスを一時的に足すとこのテストが失敗する（確認後に戻す）
  - _Depends: 1.3_
  - _Boundary: SiteDesignTests_
  - _Requirements: 1.7, 4.3, 8.3, 8.4, 8.5, 9.2, 9.3, 10.3_

- [ ] 3. 見た目の規則
- [ ] 3.1 本文の書体・行間・数字・折り返しの規則を書く
  - 固定版の生成 HTML を確認し、本文領域のセレクタを決める（特定ページの構造は前提にしない）
  - 確認用の一時的なログを、ログ形式の規則（日付のファイル名、必須のタグ一覧）を満たす形で作る。入れ子 3 階層・長いコード行・幅の広い表・長い英数字の語・タグ 5 個以上を含める。3.x の確認が終わったら削除し、コミットしない
  - 日本語システム書体の指定、行の高さ、等幅の数字、段落とリスト項目での長い語の折り返しを、既定で満たしていない項目だけ書く
  - 完了状態: ログ検証コマンドとビルドスクリプトが一時ログ込みで成功し、ログページと一覧ページで、両配色とも本文が日本語システム書体・行の高さ 1.7 倍以上で表示され、一覧の日付の桁が揃い、幅 360px でページ全体の横スクロールが無い
  - _Boundary: ExtraStylesheet_
  - _Requirements: 1.1, 1.6, 3.3, 4.5, 8.1, 8.2_

- [ ] 3.2 入れ子の箇条書き・見出し・項目間の余白の規則を書き、コードと表の既定を確認する
  - 入れ子 3 階層の行頭記号と字下げ、見出しの階層ごとの大きさと余白、箇条書き項目の間の余白を、既定で満たしていない項目だけ書く
  - コードブロック・インラインコード・表の背景・等幅書体・要素内の横スクロールがテーマ既定で満たされることを確認し、満たさない項目だけ規則を足す
  - 完了状態: ログページと一覧ページで、両配色 × 幅 1280px/360px のすべてで 3 階層の親子関係、見出しと年度・月見出しの階層差、項目間の余白が見分けられ、長いコード行と幅の広い表は要素内だけで横スクロールする
  - _Boundary: ExtraStylesheet_
  - _Requirements: 1.2, 1.3, 1.4, 1.5, 3.1, 3.2, 3.4, 4.5, 8.1, 8.2_

- [ ] 3.3 タイトル・タグ・リンク・フォーカス枠とコントラストの規則を書く
  - 生成 HTML でタグ要素のセレクタを確認し、枠線つきのラベル・折り返し・間隔を整える
  - 本文内のリンクに下線、本文領域とヘッダーそれぞれに背景と区別できるフォーカス枠を付ける
  - タイトルを書いていないログで、日付のタイトルが本文先頭に本文見出しより大きく出ることを確認する。出ない場合は補わず、要件の見直しが必要である旨を報告する
  - 開発者ツールのコントラスト表示で両配色を実測し、不足した色だけを配色別に上書きする
  - 完了状態: 両配色で、本文とリンクの文字が 4.5:1 以上、タグの枠線・切り替えボタン・フォーカス枠が 3:1 以上で、Tab キーで本文とヘッダーの操作部品を移動すると枠が常に見え、幅 360px でタグが重ならずに折り返す
  - 3.1 で作った一時ログで確認し、3.x の確認が終わったら削除する
  - _Boundary: ExtraStylesheet_
  - _Requirements: 2.1, 2.2, 2.3, 4.5, 7.1, 7.2, 7.3, 7.4_

- [ ] 4. トップページと確認手順
- [ ] 4.1 (P) トップページの見出しと説明文を書き換える
  - 見出し、サイトの目的の説明（2 文以内）、検索で過去の学びを探せる旨の 1 文に置き換える。末尾に他 spec が追記したリンク行は 1 文字も変えず、並べ替えない
  - 完了状態: 差分がリンク行に及んでおらず、ライト/ダーク × 幅 1280px/360px で、目的の説明と一覧へのリンクがスクロールせずに見え、一覧ページと検索の入口にそれぞれ 1 回の操作で到達できる
  - _Depends: 3.1_
  - _Boundary: TopPage_
  - _Requirements: 5.1, 5.2, 5.3_

  - 完了状態: 手順書だけを読んで確認を最後まで実行でき、確認項目が要件 1〜7 と 10.1・10.2 のすべての受け入れ基準を少なくとも 1 回ずつ参照している

  - 完了状態: テスト一式とビルドスクリプトが成功し、すべての確認項目を満たす。満たせない項目があれば、要件番号と状況を報告する
  - _Depends: 1.3, 2, 3.3, 4.1, 4.2_
