# Implementation Plan

> 前提: daily-log-page の全タスクが実装済みであること（`wil.records`、`scripts/build.sh` の空の生成段、`.gitignore`、`content/index.md`、`README.md`、`pyproject.toml` の pytest 設定、`deploy.yml` が存在し、`./scripts/build.sh` と `uv run pytest` が成功する状態）。この spec はそれらを作らない。

- [ ] 1. 基盤: 生成区域の宣言と共有生成ヘルパー
- [ ] 1.1 生成区域をコミット対象外にし、公開許可リストで許可する
  - 着手前に daily-log-page の成果物（上記前提）が揃い、`./scripts/build.sh` が成功することを確認する
  - リポジトリの無視設定に生成区域を 1 行追記する（既存行は変えない）
  - 共有ログ読み取り機能の公開許可リストに、生成区域内の Markdown を許可するパターンを 1 要素だけ追加する（他の規則は変えない）
  - 完了状態: 生成区域にダミーの Markdown を置いた状態で、ログ検証コマンドが成功し、`git status` に生成区域が表示されない。確認後にダミーを削除し、既存のテスト一式とログ検証コマンドが引き続き成功する
  - _Requirements: 5.4, 6.5_

- [ ] 1.2 (P) 共有生成ヘルパーを実装し、テストで振る舞いを確定する
  - 全ログを共有ログ読み取り機能で読み、描画関数が返したページ群を生成区域に書き出し、成功で 0 を返す
  - 不正なログがあれば全件のパスと理由を標準エラーに出し、何も書き出さず 1 を返す
  - ページ名が区域外を指す・絶対パス・Markdown 以外の場合は、書き出し前に失敗し何も書かない
  - 全生成器が共有するインライン文字列のエスケープ関数を置く（HTML 特殊文字を実体参照に、Markdown 記号をバックスラッシュでエスケープ）
  - 一時ディレクトリとスタブ描画関数を使うテストで、正常・0 件・不正ログ・不正なページ名を確認し、エスケープ関数のテストで特殊文字が構造を崩さない形に変換されることを確認する
  - 完了状態: 共有生成ヘルパーのテスト（エスケープ関数を含む）がすべて成功し、ヘルパーは共有ログ読み取り機能以外の機能モジュールを読み込まない
  - _Boundary: Generated, GeneratedTests_
  - _Requirements: 1.8, 3.6, 5.6, 6.2, 6.4, 8.4_

- [ ] 2. 一覧ページ生成器
- [ ] 2.1 年度計算と一覧 Markdown の描画を、テストを先に書いて実装する
  - 4 月始まりの年度計算（3/31 は前年度、4/1 は新年度、1〜3 月は前の暦年の年度）
  - 日付降順に並べ、年度と（暦年・月）が変わるたびに見出しを出す。総件数を表示し、0 件では空状態の文を出す
  - 各行に日付（ログページへのソース相対リンク）、summary（ある場合のみ）、tags（書かれた順）を出す
  - summary と tags は共有生成ヘルパーのエスケープ関数でエスケープし（一覧生成器では定義しない）、リンクや見出しの構造を崩さない
  - 完了状態: 一覧生成器のテストで、年度境界・年度内の 1〜3 月の並び・見出し書式・空のグループが出ないこと・件数・summary 有無・tags 順・エスケープ・リンク先・0 件・入力順に依存しない同一出力がすべて成功する
  - _Boundary: LogIndex, LogIndexTests_
  - _Depends: 1.2_
  - _Requirements: 1.2, 1.3, 1.4, 1.5, 1.6, 1.7, 1.8, 2.1, 2.2, 2.3, 3.1, 3.2, 3.3, 3.4, 3.5, 3.6, 5.3, 8.1, 8.2, 8.3_

- [ ] 2.2 一覧生成器をコマンドとして実行できるようにする
  - 描画関数を共有生成ヘルパーに渡す入口を作り、モジュールとして実行すると生成区域に機能名のページが書かれるようにする
  - 完了状態: リポジトリルートで一覧生成器を実行すると終了コード 0 で `content/generated/log-index.md` ができ、実際のサンプルログが掲載されている
  - _Depends: 1.2_
  - _Requirements: 1.1, 6.3_

- [ ] 3. 生成手順とサイトへの組み込み
- [ ] 3.1 ビルド前生成の唯一の登録箇所となる生成スクリプトを作る
  - 生成区域だけを削除してから、登録された生成器（現時点では一覧生成器のみ）を順に実行し、いずれかが失敗したら非ゼロで終わる
  - 実行権限を付けてコミット対象にする
  - 完了状態: 生成区域に古いダミーファイルを置いて生成スクリプトを実行すると、ダミーが消えて一覧ページだけが残る。一時的に不正なログを置くと非ゼロで終わりパスと理由が表示される。確認後に不正なログを削除し、生成スクリプトとログ検証コマンドが再び成功し `git status` に残骸が無い
  - _Requirements: 5.1, 5.5, 5.6, 6.1, 6.2, 6.5, 6.6, 7.2_

- [ ] 3.2 単一ビルド手順の生成段から生成スクリプトを呼ぶ
  - 上流のビルド手順の生成段コメントの直下に生成スクリプトの呼び出しを 1 行だけ追加し、検証段・ビルド段は変えない
  - 完了状態: ビルド手順が「検証 → 生成 → サイトビルド」の順で動き、生成スクリプトが失敗するとサイトビルドが実行されない
  - 完了状態: 生成物を消した状態からビルド手順を実行すると `site/generated/log-index/index.html` が出力される（無視設定された生成物もサイト生成ツールがビルドに含める）。出力されない場合は作業を止め、設計に戻す
  - _Requirements: 5.1, 5.2, 5.5_

- [ ] 3.3 トップページの導線と手順書を追記する
  - トップページの末尾に一覧ページへのソース相対リンクの 1 行を追加し、既存の文は変えない
  - 手順書に「一覧ページとビルド前生成」の節を追加する: 一覧は自動生成で手で編集しない、生成物はコミットしない、手元プレビューは生成してからプレビュー、生成せずにプレビューすると一覧が無い・古い・トップのリンク警告が出ること、後続機能の生成器の追加方法（生成器モジュールを作り生成スクリプトに 1 行追加）
  - 完了状態: トップページの差分が追加 1 行のみで、手順書の新しい節に手元プレビューのコマンドと注意書きと後続向け手順が載っている
  - 生成スクリプトとビルド手順への組み込み（3.1、3.2）の後に行う。先に追記すると、生成前のビルドでトップページのリンク切れとして厳格モードのビルドが失敗するため
  - 完了状態: 生成物を消した状態から実行したビルド手順が、追記したリンクを含めて成功する
  - _Requirements: 4.1, 4.4, 7.1, 7.3_

- [ ] 4. 統合検証
- [ ] 4.1 ビルド全体で一覧ページの公開とナビゲーションを確認する
  - 生成物を消した状態からビルド手順を実行し、一覧ページの HTML が出力されることを再確認する
  - 生成 HTML で、一覧の各リンクがログページへの相対 URL でルート絶対パスが無いこと、トップページのリンク、ナビゲーションの一覧項目（この時点では既定ナビ。site-design 実装後は site-design の `nav` の「学習ログ一覧」）、ログページの URL が変わっていないことを確認する。ナビ上の実際のラベルと位置を research に記録する
  - 前回の生成物が残った状態でログ検証コマンドが成功すること、`git status` に生成物が出ないこと、`uv run pytest` が全テスト成功することを確認する
  - 完了状態: ビルド手順が成功し、上記の確認結果（ナビ上のラベルを含む）がすべて満たされたことを記録できる
  - _Depends: 3.2, 3.3_
  - _Requirements: 3.2, 4.2, 4.3, 4.4, 5.2, 5.4, 8.4_
